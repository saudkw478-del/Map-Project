# AI Living Civilization — وثيقة التصميم التقني (v0.1)

> مدينة ذكاء اصطناعي حية: سكان مستقلون (AI Agents) يبدؤون بشخصين ويكوّنون عائلات ومدينة وحضارة،
> والمستخدم **مراقب فقط**. هذه وثيقة تصميم، ما فيها كود بعد.

---

## 0. ملخص تنفيذي ورأيي الصريح

**الحكم:** المشروع قابل للتنفيذ، لكن بشرط واحد: **الـ LLM ليس هو المحاكاة**. المحاكاة كود حتمي (Deterministic)،
والـ LLM "دماغ" يُستدعى في لحظات القرار والكلام فقط. هذا يحقق الاقتصاد في التكلفة ويمنع التناقض.

**مبدأ التصميم الأساسي:** `LLM proposes, Engine disposes`
الـ LLM يقترح فعلاً من قائمة أفعال مغلقة (JSON مُتحقَّق منه)، والمحرك هو اللي ينفذ ويتحقق من الشروط ويغيّر الحالة.
الـ LLM لا يغيّر حالة العالم مباشرة أبداً.

### اكتشافات مهمة (لازم تعرفها قبل البناء)

| # | المشكلة | الأثر | الحل المقترح |
|---|---------|-------|--------------|
| 1 | **عنق الزجاجة الجيني:** رجل + امرأة = أبناؤهم إخوة، ومع منع زواج الأقارب ما فيه من يتزوجون | السكان يقفون عند الجيل الثاني | **نموذج هجرة عشوائي** (Poisson): ناس يصلون للمدينة من "الخارج" بمعدل يعتمد على الرخاء والوظائف والسكن. هذي قاعدة، مو حدث مكتوب |
| 2 | **الزمن مقابل التكلفة:** حضارة تحتاج عقوداً داخل العالم، وLLM لكل يوم باهظ | 30 سنة × 100 شخص بتفاصيل كاملة ≈ آلاف الدولارات | **Level of Detail (LOD)** للزمن والسكان: وضع Micro (تفصيلي) ووضع Macro (تسريع سنوي بالقواعد، LLM للمحطات الكبرى فقط) |
| 3 | **الـ LLM ودود زيادة:** كل الشخصيات تصير مجاملة ومتشابهة | ما فيه صراع ولا دراما | ضغوط حقيقية في القواعد (ندرة، منافسة، أسرار، شخصيات صدامية) + Voice Card ثابتة لكل شخصية + كاشف تكرار |
| 4 | **"ناشئ" لا يعني "ممتع":** المحاكاة ممكن تنتج روتين ممل | المراقب يمل | مصادر دراما بنيوية: ندرة الموارد، عدم تماثل المعلومات، طموحات متعارضة، أحداث عشوائية (طقس، مرض، فرصة) |
| 5 | **"العالم لا يتوقف" يحتاج عملية تعمل دائماً** | الجهاز المغلق = عالم متوقف | Daemon على سيرفر (VPS رخيص)، والواجهة مجرد عارض. أو Catch-up عند الفتح (أضعف) |
| 6 | **التقييم صعب** | ما نعرف هل المحاكاة جيدة | مقاييس وتحقق آلي من البداية (القسم 30) |

مصادر الإلهام (للتوسع، مو للنسخ): ورقة *Generative Agents* (Stanford 2023) لنظام الذاكرة والتأمل،
ومشروع *AI Town*، وأبحاث المحاكاة الاجتماعية الكبيرة (Project Sid).

## 1. Architecture الكاملة

### 1.1 المبدأ: ثلاث طبقات

```
┌────────────────────────────────────────────────────────────┐
│ Presentation: Web UI (Observer) ←WebSocket/REST→            │
├────────────────────────────────────────────────────────────┤
│ API Layer (read-only للمراقب، write للأدمن فقط)             │
├────────────────────────────────────────────────────────────┤
│ SIMULATION CORE (حتمي، Seeded RNG، Event-sourced)           │
│  Clock · World · Needs · Movement · Economy · Institutions  │
│  ──────────── Event Bus (append-only log) ────────────     │
│  Agent System ⇄ Memory ⇄ Decision Router                    │
├────────────────────────────────────────────────────────────┤
│ AI BRAIN (غير حتمي، معزول خلف واجهة)                        │
│  LLM Gateway: budget · cache · batch · retry · validators   │
│  Embedding service (محلي)                                   │
├────────────────────────────────────────────────────────────┤
│ Storage: SQLite→PostgreSQL(+pgvector) · Snapshots · Logs    │
└────────────────────────────────────────────────────────────┘
```

### 1.2 قرارات معمارية رئيسية

1. **Event Sourcing:** كل شيء يحدث = حدث في سجل إضافي فقط (append-only). منه تُشتق الأخبار والتاريخ وTimeline كل شخص، وفيه يعاد تشغيل أي لحظة للتشخيص.
2. **Deterministic Core:** المحرك بـ Seed ثابت. الغير حتمي الوحيد هو مخرجات الـ LLM، وتُسجَّل كلها في الحدث، فإعادة التشغيل (Replay) تستخدم المخرجات المسجلة بدون استدعاء جديد.
3. **LLM Gateway معزول:** كل استدعاء عبر بوابة واحدة (ميزانية، Cache، Batch، تحقق). المحرك لا يعرف مزود الـ LLM.
4. **Lazy Evaluation:** ما نحدّث كل شخص كل Tick. الاحتياجات تُحسب بمعادلة عند الطلب، ونجدول حدث عند تجاوز العتبة.
5. **Observer-only API:** المستخدم لا يملك أي endpoint يغيّر قرارات السكان.
6. **Modular Monolith أول، ثم تقسيم:** وحدات واضحة الحدود داخل عملية واحدة، وتُقسَّم لخدمات عند الحاجة (عملاء LLM كعمال منفصلين أول شي يُفصل).

### 1.3 الوحدات (Modules)

`clock` · `world` (خريطة، مواقع، مباني) · `agents` · `needs` · `personality` · `memory` · `decision` ·
`social` (علاقات، عائلة) · `lifecycle` (حمل، ولادة، عمر، موت) · `economy` (سوق، وظائف، شركات، بنوك، أسهم، عملة) ·
`institutions` (حكومة، قوانين، ضرائب) · `justice` (شرطة، جرائم، محاكم) · `health` · `transport` ·
`events` · `news` · `history` · `llm` (Gateway) · `persistence` · `api` · `frontend`.

كل وحدة تتواصل عبر **Event Bus** وواجهات مصغرة، ولا تستورد داخلياتها من بعض.

| الخريطة | **Tiled (JSON)** | أداة مجانية معيارية |
| الاختبار | **pytest + Hypothesis** (خصائص ثابتة) | الحتمية تسمح باختبارات Replay |
| النشر | **Docker + VPS** | العالم لازم يشتغل 24/7 |

**ملاحظة LLM:** الكود يتعامل مع `LLMGateway.complete(task_type, context) -> ValidatedAction`. تغيير النموذج أو المزود أو استخدام نموذج محلي لجزء الدردشة تعديل في ملف إعدادات.

## 5. Agent Architecture

كل Agent = **بيانات + ثلاث طبقات تحكم**:

```
Agent
├─ Identity     (اسم، جنس، تاريخ ميلاد، عائلة)
├─ Traits       (شخصية، قيم، مواهب، مخاوف)         ← ثابتة نسبياً، تتحول ببطء
├─ Voice Card   (أسلوب الكلام، عينات)                 ← تُولَّد مرة، وتتحدث بمحطات الحياة
├─ State        (احتياجات، صحة، مال، موقع، وظيفة)    ← يديرها المحرك
├─ Memory       (قصير/طويل/علاقات/معتقدات)
├─ Goals/Plan   (نوايا بخطوات، يضعها الـ LLM وينفذها الكود)
└─ Control Loop:
     L0  Reflex/Needs   (كود)        ← الجوع، النوم، الطوارئ
     L1  Utility AI     (كود)        ← جدول اليوم والروتين والعمل، مرجّح بالشخصية
     L2  Deliberation   (LLM)        ← عند نقطة قرار مهمة فقط
```

- **LOD لكل Agent:** `0=نائم/بعيد (ملخص فقط)`، `1=خلفية (كود فقط)`، `2=نشط`، `3=مُراقَب/في حدث (LLM كامل)`.
- الطفل (دون سن معين) يُدار بـ L0/L1 غالباً. LLM يدخل مع المراهقة.
- **Importance Score:** يحدد LOD تلقائياً: عمدة، رئيس شركة، متهم في قضية، شخص يتابعه المراقب = أعلى.

## 6. Personality System

### 6.1 التمثيل
- **Big Five (OCEAN)** كأساس علمي، أرقام 0–1.
- **سمات إضافية:** `risk_tolerance, ambition, honesty, generosity, aggression, patience, loyalty, jealousy_prone, thrift`.
- **قيم** (3–5): عائلة، مال، سمعة، حرية، دين/تقاليد، معرفة، عدالة... مرتبة بالأولوية.
- **مواهب** (Talents) ومهارات مبدئية، **نقاط ضعف**، **مخاوف**، **رغبات**.
- **المزاج الحالي** (Mood) و**الضغط** (Stress): متغيرات ديناميكية تتأثر بالأحداث.

### 6.2 التوليد (عشان ما يكونون متطابقين)
1. العينة من **توزيعات مترابطة** (Multivariate Normal بمصفوفة ارتباط معقولة)، مو أرقام مستقلة.
2. **Archetype seeds** لضمان تنوع: نسحب نمطاً (قيادي، حذر، متقلب، حالم، مادي...) ثم نضيف ضجيجاً.
3. **ضغط ضد المتوسط:** نضمن نسبة من الشخصيات "الحادة" (قيم عالية/منخفضة)، لأن LLM وعينات عادية ينتجون متوسطات.
4. **عيوب إلزامية:** كل شخص يحصل على نقطة ضعف واحدة على الأقل لها أثر على القرار.

### 6.3 كيف تؤثر فعلاً على القرار
- **في الكود (L1):** كل فعل له `Utility = need_pressure × personality_weight × context`. مثلاً `aggression` ترفع فعل المواجهة، و`thrift` تخفض الشراء الكمالي.
- **في الـ LLM (L2):** بطاقة شخصية مكثفة (~200 توكن) في Prompt، **مع قيد**: "اختر من الخيارات المرشحة".
- **Drift:** الشخصية تتحرك ببطء بالأحداث (خيانة تخفض trust العام، نجاح يرفع الثقة). حدود الحركة لمنع التذبذب.

### 6.4 أسلوب الكلام (Voice Card)
حقول: `dialect` (فصحى/خليجي/مصري/شامي...، **قرار مفتوح عليك**)، `formality`، `verbosity`، `humor`، `temper`،
`education_style` (مفردات)، `quirks` (تعابير مكررة)، و**5–8 جمل عينة** مولّدة مرة وتُخزَّن.
تُحقن العينات (Few-shot) في Prompt الحوار. وهذا الأرخص والأفضل للاتساق بدل وصف الأسلوب بالكلمات.

## 7. Memory System

### 7.1 الطبقات

| الطبقة | المحتوى | أين | يدخل Prompt؟ |
|--------|---------|-----|--------------|
| Working | آخر ~10 أحداث/محادثة جارية | الذاكرة | دائماً |
| Episodic (Long-term) | أحداث ذات معنى بنص قصير + Embedding | جدول `memories` | عبر Retrieval |
| Important/Core | أحداث حياتية مفصلية (زواج، ولادة، خسارة، جريمة) | `life_events` | العنوان دائماً، التفاصيل عبر Retrieval |
| Relationship | ملخص + أرقام لكل علاقة | `relationships` | للأشخاص الحاضرين فقط |
| Semantic/Beliefs | استنتاجات ("سارة صادقة"، "المنافس غشاش") | `beliefs` | ذات الصلة |
| Autobiography | ملخص مُتجدّد لحياته | نص واحد ~150 توكن | دائماً |

### 7.2 الكتابة (Write Path)
1. أي حدث يمس الشخص يمر على **Importance Scorer:** قواعد حتمية (زواج=10، وفاة قريب=10، حديث عابر=1) و**LLM فقط للغامض** (دفعة Batch).
2. الأهمية تحت العتبة (مثلاً <3) **ما تُخزَّن**، أو تُدمج في ملخص يومي.
3. تُربط الذاكرة بـ `source_event_id` (فلا تنشأ ذكرى بدون حدث حقيقي).
4. **ضوضاء الذاكرة (اختياري):** الشهود يتذكرون بتفاصيل مختلفة قليلاً (يفيد في التحقيقات).

### 7.3 الاسترجاع (Read Path)
```
score = a·recency(e^(-Δt/τ)) + b·importance + c·cosine(query_embedding, memory_embedding) + d·relationship_boost
```
نبني **Context Pack** بميزانية توكن ثابتة (~600–900): Autobiography + مشاعر حالية + أهداف + أعلى K ذكريات ذات صلة + علاقة الحاضرين + الوضع الحالي. لا نرسل التاريخ كاملاً أبداً.

### 7.4 التأمل والضغط (Reflection & Compression)
- **Reflection:** عند تجاوز مجموع أهمية الأحداث الجديدة عتبة، نستدعي LLM (Batch) ليستنتج 1–3 معتقدات/دروس ويكتبها في `beliefs`.
- **Hierarchical Summaries:** أحداث → ملخص يومي → أسبوعي → سنوي. الذكريات منخفضة الأهمية تُدمج وتُنسى (Forgetting Curve).
- **Autobiography Refresh:** مرة بالسنة أو عند حدث مفصلي.

## 8. Decision Engine

### 8.1 Decision Router (من يقرر؟)

```
حدث/وقت قرار ─► هل يوجد خيار واحد واضح أو روتين؟        ── نعم ─► L1 (كود) بدون LLM
                │ لا
                ▼
        هل الأهمية < عتبة؟ (قرار صغير)                  ── نعم ─► L1: اختيار مرجّح بالشخصية + عشوائية Seeded
                │ لا
                ▼
        هل الميزانية تسمح + LOD ≥ 2؟                   ── لا ─► L1 مع تسجيل "قرار مؤجل/مبسّط"
                │ نعم
                ▼
        L2 Deliberation (LLM)  → JSON فعل → Validator → المحرك ينفذ
```

### 8.2 متى يُستدعى LLM (Triggers)
نقاط قرار يصنعها المحرك (مو الـ LLM): فرصة (عرض وظيفة، بيت للبيع)، أزمة (فقد وظيفة، مرض، دين)، **بداية تفاعل اجتماعي مهم**، أحداث حياتية (طلب زواج، إنجاب، طلاق، فتح شركة)، **مراجعة سنوية** للحياة، أدوار مؤسسية (قاضٍ، وزير، مدير).

### 8.3 المدخل والمخرج
- **المدخل:** Context Pack + **قائمة خيارات مرشحة (3–6)** يولّدها المحرك (مع شروطها) + السؤال.
- **المخرج (Structured JSON):**
```json
{ "action": "propose_marriage", "target_id": 12, "params": {...},
  "reason": "جملة قصيرة", "emotion": "hopeful", "new_intention": null }
```
- **Validator:** الفعل ضمن القائمة؟ الشروط متحققة؟ الأشخاص أحياء وحاضرون؟ وإلا يُعاد الطلب مرة، وإلا **Fallback L1**.

### 8.4 النوايا والخطط (يوفر أغلب التوكنز)
الـ LLM يضع **نية بعيدة المدى بخطوات** ("أدخّر 5,000 لأفتح مطعماً خلال سنتين")، والكود **ينفذ الخطوات** أياماً بدون استدعاءات. الـ LLM يُستدعى فقط لما تتعطل الخطة أو تظهر فرصة.

### 8.5 تسجيل القرار
كل قرار L2 يُخزَّن (`llm_calls` + حدث) مع `reason` قصير ليظهر في الواجهة كـ **AI Decision**.

## 9. Simulation Engine

### 9.1 نموذج الزمن
- **Discrete-Event Simulation** مع Priority Queue للأحداث المجدولة (بداية الدوام، عيد ميلاد، نهاية حمل)، بالإضافة لـ Tick قصير للحركة في المنطقة المراقَبة.
- **وحدة الزمن:** ثانية محاكاة. Tick الحركة = 1–5 دقائق محاكاة. السرعة قابلة للتغيير (×1 إلى ×10,000).
- **الاحتياجات (Lazy):** `value(t) = clamp(v0 - rate·(t - t0))`. نجدول حدث "وصل الجوع للعتبة" بدل تحديث كل Tick.

### 9.2 المكان
- **شبكة Tiles** (للعرض) + **رسم بياني للمواقع** (Nodes: بيوت، مصانع، محلات) بين العقد زمن سفر.
- **LOD مكاني:** المنطقة الظاهرة للمراقب = حركة Tile-by-Tile (A*). الباقي = "انتقال" بزمن سفر محسوب بدون مسار.

### 9.3 أنظمة الاحتياجات (كلها كود)
جوع، عطش، طاقة/نوم، صحة، أمان، ترفيه، علاقات، مال/سكن، تعليم. لكل واحد `rate` وعتبات وتأثير على المزاج والتصرف.

### 9.4 حلقة المحاكاة
```
while running:
    dt = clock.advance()                      # حسب السرعة
    for ev in scheduler.pop_due(dt): handle(ev)
    for agent in active_agents(lod>=2): utility_ai.step(agent)   # حركة/روتين
    interactions.resolve_proximity()          # لقاءات → قد تفتح محادثة (LLM) أو ملخص بالقواعد
    economy.daily_close_if_due()
    institutions.tick()
    events.flush(); checkpoint_if_due()
```

### 9.5 مبدأ الحفظ (Invariants)
اختبارات دائمة: مجموع المال ثابت (إلا عند مصدر/مصرف مركزي موثّق)، لا ميت يتحرك، لا شخص في مكانين، العمر منطقي، لا زواج أقارب، مخزون ≥ 0.

## 10. Relationship System

### 10.1 النموذج
لكل زوج علاقة موجهة (A→B) بأبعاد: `familiarity, affinity (-100..100), trust, respect, attraction, jealousy` + `stage` + ملخص نصي + سجل تفاعلات.

### 10.2 آلة الحالات
```
Strangers → Acquaintances → Friends / Rivals / Enemies
                         → Courting → Partners → Engaged → Married
Married → Separated → Divorced → (Reconciled)
```
الانتقال يحتاج: **شروط حتمية** (عمر بالغ، عزوبية الطرفين، مسافة قرابة، موافقة متبادلة) + **قرار** (Utility ثم LLM عند القرارات الكبرى) + **زمن** (Cooldowns لمنع القفز).

### 10.3 كيف تنمو العلاقات (بدون LLM غالباً)
كل لقاء ينتج `InteractionOutcome` بالقواعد: توافق الشخصيات، المزاج، التاريخ المشترك، وجود طرف ثالث (غيرة)... فيتحدث `affinity/trust`. الـ LLM يكتب **نص** المحادثة المهمة، لكن نتيجتها الرقمية محسوبة سلفاً (انظر القسم 21).

### 10.4 التوافق
`compat = f(تشابه القيم, تكامل السمات, العمر, الوضع الاجتماعي, الجاذبية)`. هذا فلتر مبدئي، لا يحسم لوحده.

### 10.5 الحوارات
- مولَّدة من: Voice Cards + العلاقة + ذكريات ذات صلة + "ما الذي عندهم يتكلمون عنه" (**Topic Deck** من الحالة الفعلية: عمل، مال، شكوى، خطة، خبر).
- **توليد المحادثة كاملة في استدعاء واحد** (4–8 أسطر) بدل سطر بسطر.
- ضد الحوار التافه: كاشف تشابه (Embedding/ n-gram) مع آخر محادثات الزوج، وإن تشابهت يُعاد التوليد بموضوع آخر.

## 11. Birth / Generation System

### 11.1 الحمل
شروط: شريكان، عمر خصوبة، **رغبة بالإنجاب** (من الأهداف والشخصية والاقتصاد)، صحة. الاحتمال حتمي بـ Seed. مدة الحمل 9 أشهر محاكاة، وتأثيرها على الأم (طاقة/عمل).

### 11.2 توليد الطفل (Genetics)
```
traits_child = h·mix(parent_a, parent_b) + (1-h)·sample_from_world + noise      # h≈0.4–0.5
talents      = وراثة جزئية + طفرة (Mutation) + مواهب جديدة
voice_card   = تُولَّد عند سن مبكر وتتطور (لا تنسخ الوالدين)
appearance   = معاملات Sprite (لون، طول...) وراثية جزئياً
family       = لقب الأب افتراضياً (قابل للتعديل في config)
```
الطفل **ليس نسخة**: الضجيج + الطفرة + البيئة (الأسرة، التعليم، التجارب) تغيّر المسار.

### 11.3 مراحل الحياة
طفل (0–12) ← مراهق (13–17) ← بالغ ← كبير (60+) ← تقاعد. كل مرحلة لها احتياجات وقدرات ومستوى LOD مختلف. الطفل **يرث ذكريات منظمة** عن والديه (مو نسخها)، ويكوّن ذكرياته الخاصة.

### 11.4 الوفاة والإرث
احتمال الوفاة بمنحنى عمر (Gompertz) + أمراض + حوادث. عند الوفاة: حدث، حزن عند الأقارب (Memory + Mood)، توزيع الميراث بقواعد/وصية، أخبار.

### 11.5 ضبط السكان
**Carrying Capacity** (سكن/غذاء/وظائف) يؤثر على الرغبة بالإنجاب والهجرة. لتجنب الانفجار أو الانقراض.

### 11.6 مشكلة البداية (مهمة!)
جيل التأسيس + أبناؤهم = قرابة قريبة. الحل المقترح: **عملية هجرة** (`immigration_rate = base × prosperity × housing_slack × jobs_slack`)، والواصلون أشخاص كاملون (Traits/Voice) بأسماء وعائلات جديدة. بدونها المشروع لا يتجاوز عائلة واحدة.
بديل أصعب: قرابة مسموحة بعيدة المدى، وهذا قرار أخلاقي/ثقافي يحدده "دستور العالم".

## 12. Economy System

### 12.1 قلب النظام
- **Double-entry Ledger:** كل حركة مالية = قيد مدين/دائن. اختبار ثابت: مجموع الأرصدة = ثابت.
- **سوق السلع:** كل يوم محاكاة (أو أسبوع) **Market Clearing**: عرض/طلب → تسعير تكيّفي (`price += k·(demand-supply)/supply`) مع حدود.
- **سوق العمل:** وظائف مفتوحة × باحثون: مطابقة بالمهارة والتعليم والأجر المطلوب. الراتب من إيراد الشركة.
- **الضرائب:** دخل/مبيعات (تُفعَّل مع الحكومة).

### 12.2 الشركات
كائن `Firm` له مالك (Agent)، رأس مال، موظفين، مخزون، موقع. **التشغيل اليومي بالقواعد** (إنتاج، بيع، رواتب). **قرارات المالك الاستراتيجية بـ LLM أسبوعياً/شهرياً:** توسع، تسعير، توظيف، منافس، استحواذ.
نشوء الشركة: المحرك يحسب **فجوة الطلب** (مثلاً طلب على الطعام > عرض) ويعرضها كفرصة (Trigger) على أصحاب الصفات المناسبة (طموح، مخاطرة، مدخرات).

### 12.3 المصارف والقروض
بنك = شركة مرخصة. قرض: سعر فائدة من المخاطرة، سداد، تعثر، حجز. الإفلاس بقواعد (دين > أصول لمدة).

### 12.4 سوق الأسهم (يُفتح عند الشروط)
شروط: ≥ ~1,000 ساكن و≥ 5 شركات مستقرة. **Call Auction** دوري (مو High-Frequency). الأسعار تتأثر بالأرباح، الاقتصاد الكلي، **الأخبار** (Sentiment). مستثمرون = Agents بقرارات Utility مع LLM للأفراد المهمين.

### 12.5 العملة الرقمية داخل العالم
أصل افتراضي يصدره Agent/شركة، سعره بدفتر أوامر، مضاربة وفقاعات محتملة. **مغلق تماماً داخل المحاكاة**، ولا يتصل بأي شبكة أو مال حقيقي.

### 12.6 التوازن
كل المعاملات بالقواعد، والـ LLM يقرر "ماذا أفعل" فقط، والمحرك يقرر "كم يكلف وهل ينجح".

## 13. Government System

### 13.1 الظهور (Unlock)
تظهر عندما يتجاوز المجتمع **حداً** (مثلاً ~150 شخصاً، أو نزاعات تحتاج مرجعية). قبله: عرف اجتماعي بسيط.

### 13.2 المكوّنات
- **Offices (مناصب):** رئيس، وزراء، بلدية، مدير شرطة، قاضٍ... كل منصب = Agent حقيقي.
- **Laws as Data:** قانون = (Code, نص، عقوبة، بداية). الجريمة تُعرَّف بالقانون، فتتغير بتغيره.
- **الانتخابات/التعيين:** حملة، تصويت (Agents يقررون بشخصياتهم ومصالحهم)، نتيجة بالقواعد، ثم حدث وأخبار.
- **الخدمات العامة:** صحة، تعليم، أمن، طرق، تمويلها من الضرائب. إهمالها يرفع الجريمة والمرض ويخفض الرضا.
- **الميزانية:** إيراد (ضرائب) ومصروف (رواتب وخدمات)، وعجز/دين.

### 13.3 الـ LLM هنا
**اجتماع حكومي أسبوعي/شهري = استدعاء واحد متعدد الأدوار** (رئيس + 3 وزراء) بملخص الحالة: ميزانية، جريمة، رضا، أزمات. المخرج: قرارات منظمة (تغيير ضريبة، مشروع، قانون). **الرئيس وعائلته Agents عاديون** بدون استثناءات في النظام.

## 14. Crime / Police System

### 14.1 نشوء الجريمة
قرار Agent بالقواعد + LLM للمهم: `P(crime) = f(حاجة/ضغط مالي, aggression, honesty, فرصة, ردع (احتمال الإمساك), قيم)`. **ما فيه مجرم مُحدَّد مسبقاً.**

### 14.2 الأمان والتجريد
الجرائم **مجردة وغير رسومية:** سرقة، احتيال، تخريب، اعتداء بسيط، جرائم مالية. تُمثَّل كأحداث بنوع وشدة ونتائج، بدون وصف عنف تفصيلي.

### 14.3 نموذج المعرفة (Epistemic Model) — جوهر التحقيق
- الحدث الواقعي يُنتج **أثراً/أدلة** (`evidence`: بصمة، شاهد، سجل مالي، كاميرا لاحقاً) باحتمالات وقوة.
- **لا أحد يعرف المجرم تلقائياً.** المعرفة تنتقل فقط عبر: شهود (ذكرياتهم قد تكون ناقصة)، أدلة مادية، بلاغات.

### 14.4 الشرطة
بلاغ → إرسال دورية → جمع أدلة → **ملف قضية (Case File)** → تحقيق: استجواب شهود (LLM مقيد بذاكرة الشاهد فقط) → اشتباه → قبض أو إغلاق. المحقق **يرى فقط ما في الملف**.

### 14.5 التكلفة
جرائم تافهة = قواعد فقط. جريمة ذات أهمية = ~5–10 استدعاءات LLM.

## 15. Court System

### 15.1 الإجراء (State Machine)
`شكوى/ادعاء ← مدعٍ عام يقرر الاتهام ← جلسة تمهيدية ← مرافعات ← شهود ← أدلة ← حكم ← استئناف/تنفيذ`

### 15.2 الأدوار
قاضٍ، نيابة، محامي دفاع، متهم، شهود: **كلهم Agents** بشخصياتهم وذكرياتهم، وقد يعرفون بعضاً (تضارب مصالح يُكتشف!).

### 15.3 الاستدعاءات (محسوبة)
1. **النيابة:** مرافعة من ملف القضية.
2. **الدفاع:** مرافعة من الملف + رواية المتهم.
3. **شهود:** إفادة مقيدة بذكرياتهم (أحياناً متعارضة).
4. **القاضي (نموذج أقوى):** يقرأ **القانون + الأدلة + الحجج** ويصدر حكماً منظماً مع تعليل.
5. Validator: الحكم ضمن نطاق العقوبة القانونية.
نتيجة القضية **غير محددة سلفاً**، وتتأثر بالأدلة وجودة الحجج وشخصية القاضي (نزاهة، تشدد) وقد يحدث الخطأ القضائي.

### 15.4 الأثر
سجن (غياب عن العمل، أسرة تتأثر)، غرامة (قيد مالي)، سمعة، أخبار، قابل للاستئناف.

## 16. Healthcare System

نموذج **آمن ومبسّط:** `Condition(kind, severity, progression)`. أنواع: نزلات، أمراض مزمنة، إصابات عامة، شيخوخة. لا تفاصيل طبية أو مؤذية.
- **العلاج:** زيارة عيادة/مستشفى ← تكلفة ووقت ← تعافٍ بقواعد (جودة الخدمة × شدة × تحمّل المريض).
- **المؤسسات:** عيادة، صيدلية، مستشفى، إسعاف. موظفوها Agents (أطباء/ممرضون بتعليم وخبرة).
- **أوبئة بسيطة (SIR مبسط)** اختيارية، تنتج أخباراً وضغطاً على النظام.
- الـ LLM: لا يلزم عادة. (حالات نادرة لقصة مرض مهمة).

## 18. News System

```
Event Bus ─► Newsworthiness Scorer (قواعد) ─► Top-N يومياً ─► Writer ─► Feed
```
- **Scorer حتمي:** `importance = magnitude × (#متأثرين) × شهرة الأطراف × ندرة النوع`.
- **الكاتب:** قالب جاهز للأحداث الصغيرة (صفر توكن)، **LLM (Batch)** لأهم 3–10 أخبار يومياً.
- **Grounding:** الكاتب يتلقى سجل الحدث فقط، ومحقّق يتأكد أن كل اسم/رقم في الخبر موجود في الحدث.
- **BREAKING NEWS** لأحداث فوق عتبة (وفاة شخصية عامة، إفلاس كبير، جريمة كبرى).
- **تأثير:** السكان "يقرؤون" الأخبار بحسب اهتمامهم، فتتحدث معتقداتهم ومزاجهم (ضريبة جديدة تُغضب، إفلاس بنك يُخيف). والأسهم تتأثر.

## 19. History System

- **المصدر:** سجل الأحداث. لا نكتب التاريخ يدوياً.
- **Firsts Index:** يرصد أول مرة لنوع حدث: أول مدرسة، أول شركة، أول طفل، أول جريمة، أول انتخابات.
- **Eras:** كشف حقب بقواعد (عتبات سكان، ظهور حكومة، أزمة اقتصادية).
- **Chronicler (LLM Batch):** ملخص سنوي وسردي للحقب، مبني على أحداث حقيقية فقط.
- **الواجهة:** خط زمني قابل للتصفية بالشخص/العائلة/الموضوع، مع روابط للأحداث الأصلية.

## 20. Time / Persistence System

- **WorldClock:** `sim_time = sim_time0 + (wall_now - wall_t0) × speed`. المراقب يغيّر السرعة أو يوقف، لكن هذا لا يتحكم بالسكان.
- **Checkpointing:** Snapshot كل N دقائق محاكاة + سجل أحداث. بعد انهيار: استرجاع آخر Snapshot ثم إعادة تشغيل الأحداث.
- **Daemon:** عملية السيرفر تحتفظ بالعالم حياً. الواجهة تتصل وتنفصل بحرية.
- **السرعات المحسوبة:** وضع Micro (×1–×60)، وضع Macro (تسريع، قواعد وأحداث كبرى).
- **سلامة البيانات:** نسخ احتياطي يومي، Migrations، ومفتاح إصدار للمخطط.

## 21. AI Token Optimization

### 21.1 ما يحتاج LLM وما هو كود فقط

| الوظيفة | LLM؟ |
|---------|------|
| الوقت، الحركة، الاحتياجات، العمر، الحمل | كود |
| الرواتب، الأسعار، الضرائب، الحسابات، المخزون | كود |
| روتين اليوم (عمل/أكل/نوم) | كود (Utility AI) |
| نتيجة التفاعل الرقمية (affinity, trust) | كود |
| الأخبار الصغيرة، السجل التاريخي | كود/قوالب |
| **نص** المحادثات المهمة | LLM |
| قرارات حياتية كبرى (زواج، شركة، وظيفة، جريمة) | LLM |
| تخطيط النوايا بعيدة المدى | LLM |
| التأمل واستخراج المعتقدات | LLM (Batch) |
| القضاء، الحكومة، قرارات المديرين | LLM (نموذج أقوى) |
| ملخصات الأخبار الرئيسية والتاريخ | LLM (Batch) |

### 21.2 أنواع الاستدعاءات وأحجامها التقريبية

| الاستدعاء | التكرار | Input | Output | النموذج |
|-----------|---------|-------|--------|---------|
| محادثة (زوج كامل) | حسب الأهمية | ~1,200 | ~350 | Haiku 4.5 |
| قرار (L2) | ~0.3–0.5/شخص/يوم | ~1,500 | ~200 | Haiku / Sonnet 5.5 |
| تأمل/ضغط ذاكرة | كل 1–3 أيام للمهمين | ~1,200 | ~250 | Haiku (Batch -50%) |
| مؤسسي (قاضٍ، حكومة) | نادر | 3–6K | 0.5–1.5K | Sonnet 5.5 |
| أخبار/تاريخ | يومي (Top-N) | ~600 | ~100 | Haiku (Batch) |

### 21.3 تقدير الاستهلاك (فرضيات، نقيسها فعلياً في المرحلة 1)
- شخص بالتفصيل الكامل ≈ **1.8 استدعاء/يوم محاكاة** ≈ **2.3K توكن دخل + 0.5K خرج** ≈ **2.8K توكن/يوم** ≈ **~120 توكن/ساعة محاكاة**.
- تكلفة الاستدعاء بـ Haiku 4.5 ($1 / $5 لكل مليون): **~$0.003**. بـ Sonnet 5.5 ($2 / $10): ~$0.006. (الأسعار من جدول Anthropic المخزن بتاريخ 2026-09-25، تأكد منها وقت التنفيذ.)

| عدد السكان | تفصيل كامل لكل الناس | مع LOD (≈15% من الكلفة) |
|-----------:|---------------------:|-------------------------:|
| 2 | ~$0.01 / يوم محاكاة | ~$0.002 |
| 10 | ~$0.05 | ~$0.007 |
| 100 | ~$0.5 | ~$0.07 |
| 1,000 | ~$5 | ~$0.75 |
| 10,000 | ~$50 | ~$7.5 |

**للتحويل لتكلفة حقيقية:** `التكلفة اليومية = تكلفة يوم المحاكاة × (أيام محاكاة لكل يوم حقيقي)`.
مثال: 1,000 ساكن مع LOD بسرعة **يوم محاكاة/ساعة حقيقية** ≈ $18/يوم حقيقي. 100 ساكن ≈ $1.7/يوم.
**انتبه:** بسرعة يوم/ساعة، سنة محاكاة = ~15 يوم حقيقي. لذلك الأجيال تحتاج وضع Macro.

### 21.4 أدوات التقليل (بالترتيب)
1. **الكود أول:** أغلب الحياة بدون LLM.
2. **Event-driven فقط:** لا استدعاء بدون Trigger.
3. **Plans/Intentions:** LLM يخطط، الكود ينفذ أياماً.
4. **Lazy Dialogue:** نتيجة المحادثة تُحسب بالقواعد وتُحفظ (موضوع، مزاج، أثر)، ونص الحوار يُولَّد **فقط إذا فتح المراقب المحادثة**، متسقاً مع النتيجة المخزنة. أكبر توفير.
5. **Prompt Caching:** البادئة الثابتة (قواعد العالم، Voice Card، الشخصية) في بداية الـ Prompt، والمتغير في الآخر. قراءة الكاش أرخص بكثير.
6. **Batch API (-50%)** لكل ما ليس عاجلاً (تأمل، تاريخ، أخبار، Catch-up).
7. **Context Selection:** Context Pack بميزانية ثابتة، Retrieval مو نسخ كامل.
8. **Response Cache:** مواقف متكررة (تحية روتينية بين معارف) بقوالب/Cache محلي.
9. **نموذج صغير للحجم، كبير للأهمية** (Router حسب Importance).
10. **Embeddings محلية** (بدون تكلفة API).
11. **حد ميزانية يومي صارم** داخل `LLMGateway`: عند الوصول، تنخفض الطبقات تلقائياً إلى L1 (لا توقف).
12. **نموذج محلي مفتوح** لدردشة الخلفية في النطاق 5K+ (اختياري).

## 22. تشغيل العالم بدون مستخدم

1. **Daemon دائم** على سيرفر. لا يحتاج واجهة.
2. وضع **Idle LOD:** عند غياب المراقبين، تنخفض كل الطبقات إلى L1 + **أحداث كبرى فقط بـ LLM** (زواج، ولادة، شركة، جريمة، قضية)، والمحادثات "Lazy".
3. **ميزانية Idle** منفصلة وأصغر.
4. **Catch-up** (للتشغيل غير الدائم): عند فتح البرنامج، نشغّل المحاكاة بسرعة قصوى بـ L1 على الفترة الفائتة، مع سقف محدد، ثم نعرض "ماذا حدث وأنت غائب" (**Digest** من الأحداث).
5. **Digest:** عند عودة المراقب نعرض ملخصاً: زواج/ولادة/وفاة/شركات/جرائم/تغيرات الأسعار.
6. المراقب لا يأمر السكان أبداً. يقدر فقط يغيّر **السرعة والإيقاف** (وهي لا تتحكم بالقرارات).

## 23. التوسع من 2 إلى 10,000

| الحجم | ما يتغير |
|------:|----------|
| **2–10** | عملية واحدة، SQLite، Fake LLM للاختبار، كل شيء بتفصيل كامل |
| **50–100** | LOD، Batch للتأمل، فهرسة Embeddings، Profiling |
| **500–1,000** | PostgreSQL + pgvector، عمال LLM منفصلون (Redis)، Spatial Partitioning، Cache، ميزانية صارمة |
| **5,000–10,000+** | تقسيم المحاكاة إلى **مناطق** (Sharding) بسكان لكل منطقة، نماذج محلية للدردشة، **Vectorization (NumPy)** للاحتياجات والاقتصاد، تجميع الاستدعاءات (Batching) |
| **>10K** | محاكاة تجميعية للمناطق البعيدة (Statistical/Agent Aggregation)، والتفصيل فقط حيث المراقب |

**قاعدة:** في كل مرحلة نقيس (زمن Tick، توكن/وكيل/يوم، تكلفة/يوم) ولا نوسع قبل ما تثبت الأرقام.

## 26. Security

- **المراقب read-only:** عزل صلاحيات على مستوى الـ API (JWT/جلسات)، وأدمن منفصل.
- **مفاتيح الـ LLM** في السيرفر فقط (متغيرات بيئة/Secret Manager)، ولا تصل للواجهة.
- **Prompt Injection بين الوكلاء:** حوارات الوكلاء تدخل Prompts لوكلاء آخرين، فهي قناة هجوم/انحراف. الحل: تُعامل كـ **بيانات مقتبسة** داخل وسوم، والمخرجات JSON مقيد من قائمة أفعال، والـ Validator يرفض أي فعل خارج القواعد.
- **حدود التكلفة:** سقف يومي/ساعي + Circuit Breaker + Kill Switch + تنبيه.
- **التعامل مع `refusal`:** عند رفض النموذج يُعتمد Fallback L1 وتُسجَّل الحالة.
- **المحتوى:** الجرائم والأمراض مجردة وغير رسومية (حسب السياسات).
- **بيانات حقيقية:** لا يوجد مستخدمون حقيقيون داخل العالم؛ ولا تخزين بيانات شخصية. لا اتصال بأموال حقيقية أبداً.
- **عام:** HTTPS، Rate Limiting، CORS ضيق، تحديث الاعتماديات، نسخ احتياطي مشفر.

## 27. منع التصرفات الغبية والمتناقضة

1. **LLM لا يخترع حالة:** الحقائق (المال، المكان، الأحياء، العلاقات) تُحقن من المحرك، و**مرجعها الوحيد** قاعدة البيانات. الـ LLM يختار ولا يقرر الواقع.
2. **قائمة أفعال مغلقة + Validator** (شروط مسبقة) + Fallback كود.
3. **ترشيح قبل الاختيار:** المحرك يرتب الخيارات بـ Utility ويعطي الـ LLM أفضل 3–6 فقط. هذا يمنع الأفعال الشاذة.
4. **Cooldowns وحدود معدل:** مثلاً لا يطلب الزواج 5 مرات في أسبوع، ولا يغيّر وظيفته يومياً.
5. **اتساق الشخصية:** بطاقة Traits ثابتة + Voice Card + "ثوابت" (لا يتصرف عكس قيمه العليا إلا بدافع قوي مسجل).
6. **اتساق الزمن والعمر والجنس والمعرفة:** فحوصات آلية، وAgent لا يعرف إلا ما في ذاكرته (Epistemic Model).
7. **كاشف التكرار والحلقات:** (Loop Detector) يرصد تكرار نفس الفعل/الحوار ويكسره بسياق جديد.
8. **تحقق الأخبار والذكريات:** كل نص مربوط بحدث، ومُدقق أسماء/أرقام.
9. **Invariants + Property Tests** (القسم 9.5).
10. **Replay Tests** بالـ Seed لاكتشاف الانحراف بعد كل تعديل.
11. **Believability Eval:** عينة محادثات/قرارات تُقيَّم دورياً (LLM-as-judge + مراجعة بشرية) بمقاييس الاتساق.
12. **Temperature منخفض** للقرارات، أعلى للحوار، وبـ Seed في الاختبار.

## 28. كيف تتذكر الشخصيات الأحداث المهمة

1. **الحدث يُسجَّل أولاً** في `events` (حقيقة)، ثم يُنتج **ذاكرة شخصية** لكل طرف متأثر بنص من منظوره + مشاعر.
2. **الأهمية** تحدد البقاء: الأحداث العالية تدخل `life_events` (لا تُنسى ولا تُضغط).
3. **عند اتخاذ القرار:** الـ Retrieval يستحضر ذكريات ذات صلة (بالشخص/الموضوع/المشاعر). مثلاً قبل التعامل مع سارة، تظهر "ساعدتني في أزمة المال"، "اختلفنا على العقد".
4. **التأمل** يحول الذكريات المتفرقة إلى معتقدات ("سارة تعتمد عليها").
5. **التشويه الطبيعي:** الذكريات القديمة قليلة الأهمية تبهت وتُدمج، والمهمة تبقى.
6. **تنتقل المعرفة** بين الناس بالمحادثة والأخبار (والإشاعات قد تشوه!).

## 30. خطة التطوير (MVP ثم التوسع)

### المبدأ
**نبدأ بـ Simulation Engine وArchitecture الوكلاء، لا بالرسوميات.** كل مرحلة تنتهي بشيء يعمل ويُختبر. وكل مرحلة تُقاس تكلفتها.

### المرحلة 0 — الهيكل (أسبوع تقريباً)
Repo، الساعة (Clock)، Scheduler، Event Bus + سجل الأحداث، Seeded RNG، DB (SQLite)، Snapshot/Replay، **Fake LLM** للاختبار، CLI لتشغيل العالم، اختبارات Invariants.
**معيار النجاح:** عالم فيه شخصان يتحركان بين 5 مواقع ويأكلون وينامون (بدون LLM)، ويعيد Replay نفس النتيجة بالضبط.

### المرحلة 1 — العقل والذاكرة
Personality + Voice Card، LLMGateway (ميزانية، Cache، Validator)، Decision Router + Utility AI، Memory Stream + Retrieval، محادثات بين الشخصين، تسجيل التكلفة.
**المعيار:** حوارات متنوعة وغير مكررة، وقرارات متسقة مع الشخصية، وقياس توكن/يوم.

### المرحلة 2 — العلاقات والعمل
آلة حالات العلاقات، خطوبة/زواج، وظيفة بسيطة ومال (Ledger)، دخل/مصروف، سكن.
**المعيار:** علاقة تتطور بشكل غير مكتوب مسبقاً، وLedger متوازن.

### المرحلة 3 — الأجيال والاستمرارية
حمل، ولادة، توليد الأطفال (Genetics)، مراحل العمر، وفاة وإرث، **نموذج الهجرة**، Daemon + Checkpoint + Digest، Idle LOD.
**المعيار:** يدخل المراقب بعد ساعات ويجد أحداثاً حدثت، والعالم يصل لـ 3 أجيال بدون تدخل.

### المرحلة 4 — الواجهة (MVP للمراقب)
خريطة 2D بسيطة، بروفايل، Follow Mode، Timeline، News مبسط، Digest.

**هنا ينتهي الـ MVP المطلوب** (رجل، امرأة، خريطة 2D، احتياجات، شخصيات، ذاكرة، محادثات، علاقات، عمل، مال، زمن، إنجاب، طفل، حفظ، استمرار).

### مراحل التوسع (كل واحدة قابلة للتجربة منفصلة)
5. **قرية:** عدة عائلات، محلات، مدرسة، تعليم، سوق سلع.
6. **اقتصاد حقيقي:** شركات، توظيف، بنوك، قروض، إفلاس.
7. **حكومة وقوانين وضرائب** + أخبار وتاريخ كاملان.
8. **جريمة + شرطة + محاكم** (Epistemic Model + Case Files).
9. **صحة ومستشفيات + مواصلات وسيارات.**
10. **بورصة وعملة رقمية.**
11. **التوسع:** 100 ← 1,000 ← 10,000 (قياس + Sharding + Vectorization).
12. **الرسوميات** (Tilesets، أنيميشن) والصقل.

### مقاييس متابعة من اليوم الأول
- **التكلفة:** توكن/وكيل/يوم، $/يوم محاكاة.
- **التنوع:** مسافة Traits، تنوع المفردات، تنوع القرارات.
- **الاتساق:** نسبة رفض الـ Validator، عدد التناقضات المكتشفة.
- **الحياة:** معدلات زواج/ولادة/وفاة، توزيع الثروة (Gini)، بطالة.
- **الاستقرار:** عدم الانقراض/الانفجار، سلامة الـ Invariants.
- **الأداء:** زمن Tick، عدد الاستدعاءات/ثانية.
