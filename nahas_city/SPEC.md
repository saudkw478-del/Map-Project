## Story ("مدينة النحاس", from the folk tales of the Thousand and One Nights — NOT scriptural)
Travellers found a legendary city of brass whose people turned to statues. Each night it awakens. The players are a desert caravan that woke in the sand at night with a cursed **lantern**. To save the sleepers they must earn **7 brass seals (أختام النحاس)** from 6 trials across huge lands and two other worlds, then open the city gate and defeat the last guardian, **"الحارس النحاسي"** (a colossal brass djinn-guardian) in the palace courtyard. The sea of stars and the ember land are the "other worlds".

## Version rules (important)
* Functions live in `data/nahas/function/` (singular). Loot tables in `loot_table/`, advancements in `advancement/`, tags in `data/minecraft/tags/function/`.
* Commands must pass the `mecha` linter (beet). Every name must exist in the registries (see tools below). No entity/item NBT that is version-fragile: use `Tags`, `PersistenceRequired`, `Invulnerable`, `NoAI`, `NoGravity`, `Silent`, `Rotation`; avoid `ArmorItems/HandItems/attributes/Offers`. Use `item replace`, `loot`, `effect`, `particle`, `playsound`, `title`, `tellraw`, `scoreboard`, `execute`, `damage`, `tp`, `spectate`, `gamemode`, `random`, `schedule`, `execute in <dimension>`. Risky/renamed commands (gamerule names, time, weather) go in tiny macro functions like `$gamerule mob_griefing $(v)` called with `{v:"false"}`, one command per function (old+new name variants).
* Custom item look: components via loot `set_components`/`set_name`, `"minecraft:item_model":"nahas:<id>"` (resource pack provides `assets/nahas/items/<id>.json`). Custom names in loot tables are text-component JSON objects.
* `text_display`/`block_display` entities: allowed for 1.21.4 (text is a JSON *string*); keep them in isolated functions (`nahas:fx/...`) so a failure only breaks the effect.
* Scoreboard prefix `nh_` for objectives; fake players start with `#`. Triggers (all Arabic help text): `nh_role`, `nh_go`, `nh_shop`, `nh_quest`, `nh_power`, `nh_map`, `nh_help`, `nh_ask` (AI hint), `nh_start`.

## Hook interface between CORE and STORY agents
CORE owns `data/nahas/function/{core,trial,items,shop,portal,boss,role,quest}/`, tags `load`/`tick`, loot tables, advancements. STORY owns `data/nahas/function/{intro,npc,story,fx,ambient,hook}/`, `ai/`, docs of story. CORE's per-tick function calls `function nahas:hook/tick` (if it exists) and once per second `function nahas:ambient/second` and `function nahas:npc/second`. STORY must implement these hook functions (executed as the relevant player unless noted; CORE calls them, STORY writes them): `hook/first_join`, `hook/seal_gained` (score `#seals`, player got seal number in score `@s nh_lastseal`), `hook/trial_start` (score `#trial` = 1..7), `hook/trial_done`, `hook/city_open` (6 seals done), `hook/boss_start`, `hook/boss_phase` (`#phase`), `hook/boss_defeated` (final victory: big cinematic ending), `hook/player_death`. CORE exposes for STORY: `#seals` (0..7 shared), `#trial`, `#phase`, per-player `nh_gold`, `nh_role`, tag `nh_seen`.
Roles (CORE): 4 roles with a passive + active power via `/trigger nh_power`: المستكشف, الفارس, الحكيم, الظلّ (design freely, Arabic).
